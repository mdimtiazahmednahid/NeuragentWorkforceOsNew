# Workforce OS - Production Troubleshooting & DevOps Log

This document serves as a permanent record of the critical bugs encountered during the deployment of Workforce OS to InfinityFree (shared hosting environment), and the exact technical steps taken to resolve them. 

---

## 1. Database Key Length Error (SQLSTATE 1071)
* **Problem:** InfinityFree uses an older MariaDB version that restricts index keys to a maximum of 1000 bytes. Laravel's default `utf8mb4` encoding (255 characters per string) exceeded this limit when creating composite indexes (e.g., on the `failed_jobs` table).
* **Solution:** 
  1. Updated `AppServiceProvider.php` inside the `boot()` method to include `\Illuminate\Support\Facades\Schema::defaultStringLength(191);`
  2. Manually edited the `create_jobs_table` migration to explicitly limit string lengths (e.g., `$table->string('uuid', 100)->unique();`).

## 2. The `symlink()` Disabled Restriction
* **Problem:** InfinityFree completely disables the PHP `symlink()` function for security reasons. This caused immediate 500 Server Errors when uploading files or viewing profile pictures, because Laravel relies on a symlink connecting `storage/app/public` to `public/storage`.
* **Solution:** Bypassed the symlink requirement entirely by re-routing the storage disk. Edited `config/filesystems.php` and changed the `public` disk's `'root'` path directly to the public folder: 
  `'root' => public_path('storage')`

## 3. Database Column Mismatches (500 Errors on Dashboard)
* **Problem A (`due_date` vs `deadline`):** The dashboard crashed because the `tasks` table was queried for a `due_date` column, but the migration had created the column as `deadline`.
  * *Solution:* Updated `dashboard.blade.php` to query `deadline`.
* **Problem B (`end_time` vs `break_end`):** The `user-quick-stats` component crashed the dashboard while calculating Worked Hours because it queried `start_time` and `end_time` from the `break_sessions` table, instead of the actual `break_start` and `break_end`.
  * *Solution:* Updated `user-quick-stats.blade.php` to use the correct schema column names.

## 4. CSS Completely Broken on Mobile (Mixed Content)
* **Problem:** The site layout loaded perfectly on desktop but looked completely broken (raw HTML and giant SVGs) on mobile devices, specifically iOS Safari. This happened because InfinityFree sits behind a proxy, making Laravel think the request was HTTP. Safari strictly blocks HTTP stylesheets on HTTPS websites (Mixed Content policy).
* **Solution:** 
  1. Edited `.env` to ensure `APP_URL=https://neuragent.rf.gd`.
  2. Forced HTTPS generation in `AppServiceProvider.php` using `\Illuminate\Support\Facades\URL::forceScheme('https');`.

## 5. The Vite `public/hot` Dev-Server Bug
* **Problem:** Even after forcing HTTPS, some browsers refused to load the CSS. This occurred because a local `public/hot` file (generated by running `npm run dev` on a local Mac) was accidentally zipped and uploaded to the live server. This file told Laravel to ignore the compiled CSS and try to load styles from `localhost:5173`.
* **Solution:** Created a script to delete the `public/hot` file from the production server, forcing Laravel to correctly read from `public/build/manifest.json`.

## 6. Hardcoded Dark Mode & Theme Settings
* **Problem:** The application was permanently stuck in Dark Mode. The Flux UI appearance settings (Light/Dark/System) were ignored because `class="dark"` was hardcoded into the `<html>` tags of all layout files.
* **Solution:** 
  1. Removed `class="dark"` from `header.blade.php`, `sidebar.blade.php`, and all `auth` layouts.
  2. Moved the Flux UI theme toggler directly into the main Profile Details page (`profile.blade.php`) to make it easily accessible to all users.

## 7. Data Reconstruction & Task Seeding
* **Problem:** During the intensive debugging, the production database tables were completely dropped and rebuilt. The client required all local data (Users, Departments, Projects) to be synced back to production without SSH access.
* **Solution:** Engineered custom PHP injection scripts (`restore_all.php`, `taskadd.php`, `ashraf.php`) that connected to the live MySQL database via the browser to cleanly repopulate Users, Roles, Projects, and dynamically generate sequential, scheduled daily tasks for specific employees.
